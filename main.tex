\subsection{Generative models using Semantic IDs}
Works that generate semantic IDs for generative recommendation can be generally classified along the following three axes:

\begin{enumerate}
    \item Whether the semantic ID generation and generative recommendation models are independently trained
    \item Whether pretrained item embeddings were used
    \item Whether any complementary information to train semantic IDs apart from item information was utilized
\end{enumerate}

Table \ref{table:ModelClassification} briefly summarizes the models that fall into any of the 8 possible combinations for these axes. It is to be noted that not all categories may have models associated with them and not all models may fall strictly into one of these categories. Focus of some of the research may also not be a good fit for such classification. In \cite{2025RPG_hou2025generatinglongsemanticids}, the primary objective of the authors have been to generate long and more expressive semantic IDs using a framework that can generate them in parallel. The classification in Table \ref{table:ModelClassification} does not account for this. This generalized classification, however, allows us to organize the research areas in this space in a way that is more suitable for real-world use since each axis focuses on a different aspect of the generative recommendation process.

Independent training of SID generation and generative recommendation allows the semantic IDs to be decoupled from its usage in recommendation. The SID, in this case, is a more truthful representation of its corresponding item and its content, and not of the item a user is likely to click on next. This is primarily useful if SIDs need to be also used for item organization or for recommending items solely on content similarity. The second axis focuses on the cost aspect of the recommendation process. Training an embedding model tailored to a specific catalog of items may improve the quality of embeddings but in practice that is often costly and infeasible. Using a pretrained embedding model to generate embeddings using item features as input is more cost effective and practical for most use cases. The last axis depicts whether any other data apart from the item contents, such as any user-level preferences and co-occurence features, is used as part of generating the SIDs. Although, some models use some kind of information during the generative process to personalize the recommendations for a specific user, usage of such information to generate semantic IDs is limited.

For any real-world use case, the appropriate choice of architecture can be narrowed down by asking the following questions:

\begin{enumerate}
    \item Should semantic ID of an item be a representation of its contents or of the item that should follow it in the recommendation sequence?
    \item Is it feasible to train a custom embedding model for encoding the item contents?
    \item Should semantic IDs also encode any other information such as user-level preferences and co-occurence features?
\end{enumerate}
