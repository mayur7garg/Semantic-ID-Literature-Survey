\section{Introduction}

The evolution of recommender systems has been characterized by a continuous drive to better understand user preferences and deliver highly relevant content. Traditional recommendation paradigms, such as collaborative filtering and matrix factorization, have largely been superseded by deep learning-based approaches capable of capturing complex, non-linear relationships in user-item interactions. Recently, inspired by the unprecedented success of Large Language Models (LLMs) in natural language modelling, there has been a paradigm shift towards utilizing the same for generative recommendation. Instead of relying on traditional ranking and scoring mechanisms over a vast candidate pool, generative recommendation frames the task as a sequence-to-sequence problem, where the model directly predicts the next item a user is likely to interact with based on their historical interactions.

A critical challenge in this paradigm is how to effectively represent items. Traditional atomic item IDs, which assign a unique integer to every item in the catalog, scale poorly with large catalogs, suffer from the cold-start problem for new items, and crucially, do not inherently capture any semantic relationship between items. To overcome these limitations, the concept of Semantic IDs (SIDs) has emerged as a promising solution. Semantic IDs represent each item not as a single, meaningless integer, but as a tuple or sequence of discrete tokens (codewords) derived from the item's semantic features (e.g. name, text descriptions, images). By quantizing item embeddings into discrete codes, SIDs map semantically similar items to similar ID sequences providing a good balance between memorization and generalization. Recommendation models can leverage shared prefixes or tokens to infer relationships, handle cold-start scenarios, and generate more diverse recommendations.

This literature survey provides a comprehensive overview of the recent advancements in generative recommendation using Semantic IDs. We systematically explore the foundational concepts, including various embedding quantization strategies like RQ-VAE and OPQ used to generate these IDs. Furthermore, we categorize existing architectures based on their training methodologies and highlight the trade-offs between independently and jointly trained models. Finally, we discuss the evaluation metrics used to assess both the quality of the generated Semantic IDs and the downstream recommendation performance, providing a structured understanding of this rapidly evolving field.

\section{Foundational concepts}
\subsection{Generative recommendation}
For a user $u$ and its ordered interaction history $S = [i_1, i_2, \cdots, i_T]$ where $i_t \in I$ for last $T$ interactions with item space $I$, the objective of a generative recommendation model is to predict item $i_{T+1}$ that the user is most likely to interact with. By framing the interaction history as an ordered sequence, generative models analogously treat next item prediction as a next word prediction task in natural language modelling. Since most generative models perform this process in an auto-regressive manner, the probability $P$ of the next item predicted by the recommendation model can be expressed as shown:

\begin{equation} \label{eq:GenRec}
P (i_{1:T} | u, S) = \prod P(i_t | i_{<t}, u, S)
\end{equation}

\subsection{Semantic IDs}
The items in Eq. \ref{eq:GenRec} can be represented either by a single integer (Item ID) or a tuple of integers (semantic IDs). Atomic item IDs, despite being effective in certain situations, do not generalize well specifically when interaction data is sparse. Semantic IDs discretize content representations in a sequence of tokens which for an item $i$ can be expressed either as an ordered set $s_i = [s^1_i, s^2_i, \cdots, s^L_i]$ or an unordered set $s_i = \{s^1_i, s^2_i, \cdots, s^L_i\}$  of integer codes where $L$ is the number of semantic codes used per item. Generally, $L$ refers to the number of codebooks used during quantization of the item embeddings such that each codebook contributes one semantic ID (refer to Section \ref{subsection:Quantization}) and the entire sequence uniquely identifies said item. Most state-of-the-art models prioritize ordered semantic IDs to leverage the auto-regressive decoding by language models so that they can generate one integer code at a time. By using semantic IDs as item identifiers, the interaction history from the previous section can be expressed as $S' = [s_1, s_2, \cdots, s_T]$. Eq \ref{eq:GenRec} now becomes:

\begin{equation} \label{eq:SIDGenRec}
P (s_{1:T} | u, S') = \prod P(s_t | s_{<t}, u, S')
\end{equation}

Embeddings for the entire item set require $|I| \cdot d$ floating point numbers to be stored, where $d$ is the dimensionality of the embeddings. Most semantic IDs require $L$ integers per item and an additional overhead of storing $L$ codebooks, each of which contains $K$ reference embeddings. The total space requirement is thus bounded by $|I| \cdot L + L \cdot K \cdot d$ (assuming floats and integers take up the same number of bytes). In practice, $L \ll d$, and each integer code can be represented by much fewer bytes than floats, which enables SIDs to store the semantic information of the items in orders of magnitude less space.

\subsection{Embedding quantization strategies}\label{subsection:Quantization}
The most popular approach to create semantic IDs is to generate item embeddings and then quantize them into a sequence of integer codes. Generally, item embeddings are created from a pretrained model using textual or multi-modal item features which are then fed into a quantization algorithm. In \cite{2026UniSID_jiang2026endtoendsemanticidgeneration}, the authors even showcased that item embeddings and their semantic IDs can be generated as part of a single training loop.

The choice of quantization strategy not only determines the quality and speed of SID generation, it also affects how semantic IDs are represented. Residual quantization to generate SIDs, which was popularized by Rajput
et al. \cite{2023TIGER_rajput2023recommendersystemsgenerativeretrieval} using an RQ-VAE \cite{RQVAE_lee2022autoregressiveimagegenerationusing} model, results in semantic IDs which have a hierarchical relationship between subsequent codes. On the other hand, in \cite{2025RPG_hou2025generatinglongsemanticids, 2026ACERec_xia2026unleashpotentiallongsemantic} OPQ \cite{OPQ} is used to generate orthogonal subspaces which can be independently quantized. Furthermore, to address the codebook utilization imbalances inherent in standard residual quantization, alternate strategies based on K-Means clustering have been proposed. Common strategies are listed in the following subsections.

\subsubsection{RQ-VAE}\label{subsubsection:RQ-VAE}
Figure \ref{fig:RQ-VAE} provides an overview of Residual-Quantized Variational AutoEncoder (RQ-VAE) \cite{RQVAE_lee2022autoregressiveimagegenerationusing} architecture. RQ-VAE uses residual quantization at multiple levels to generate a series of codewords or semantic IDs. Item embedding $e_i$ is first encoded by a DNN encoder $\epsilon$ to yield $z_i = \epsilon(e_i)$. To generate $L$ semantic IDs, the model consists of $L$ codebooks. Each codebook consists of $K$  $d$-dimensional codewords i.e. $C^l = [c_1^l, c_2^l, \cdots, c_K^l]$. At level 1, the residual is simply defined as $r_i^1 = z_i$. At each level $l$, the corresponding semantic ID and the residual for the next step is defined as given in Eq \ref{eq:RQ-VAE}.

\begin{figure}
    \centering
    \includegraphics[width=1\textwidth]{images/RQ-VAE architecture.png}
    \caption{RQ-VAE \cite{RQVAE_lee2022autoregressiveimagegenerationusing} architecture}
    \label{fig:RQ-VAE}
\end{figure}

\begin{equation} \label{eq:RQ-VAE}
\begin{split}
s_i^l = \operatorname*{argmin}_{k=1..K} ||r_i^l - c_k^l||_2^2\\
r_i^{l+1} = r_i^l - c^l_{s_i^l}
\end{split}
\end{equation}

Once we have all the semantic IDs ($s_i = [s^1_i, \cdots, s^L_i]$) and their corresponding codewords ($[c^1_{s_i^1}, \cdots, c^L_{s_i^L}]$), $z_i$ is reconstructed using $\hat{z_i} = \sum\limits_{l=1}^L c^l_{s_i^l}$. The reconstruction $\hat{z_i}$ is then passed through the decoder $\delta$ to yield $\delta(\hat{z_i})$ which should be close to the original input embedding $e_i$. To handle collisions between items with identical semantic IDs, Rajput et al. \cite{2023TIGER_rajput2023recommendersystemsgenerativeretrieval} append an extra token to make the items unique. The encoder, the autoencoder and the decoder are jointly trained using two loss functions - 1. Reconstruction loss that aims to minimize the difference between the input embedding and the output embedding from the decoder module and 2. Commitment loss which aims to minimize the difference between the residual and the chosen codeword at each level to prevent the residuals from drifting apart.

The SIDs generated by RQ-VAE possess multiple useful attributes for search and recommendation tasks. Since each ID is generated from the residual from the previous layer, the SIDs follow a hierarchical sequence creating a tree-like structure. As we go down the sequence, the SIDs progressively capture finer details of the item. This also enables similar items to share common prefix tokens allowing any downstream applications to infer relationship between items. Additionally, this tree-based hierarchy can be expressed as a Trie which allows for efficient and constrained beam search during inference. Length of the common prefix also becomes a crude measure to quantify item similarity as very similar items will have a longer common prefix compared to items which have very little similarity. Items can be mapped to other items which differ only in the last few SIDs which can help in item discovery and cold-start issues in recommendation.

\subsubsection{OPQ}
Optimized Product Quantization is an improvement on the PQ vector quantization strategy. To quantize with PQ, a high-dimensional embedding vector is broken into $L$ distinct, equal, low-dimensional sub-vectors. Each sub-vector is clustered into $K$ clusters and is represented by the ID of the centroid of the assigned cluster. Each group of cluster centroids represent a codebook of size $K$ with the ID of the centroid representing its semantic ID. Standard Product Quantization, however, suffers from independence of subspace assumption and doesn't account for correlated dimensions. OPQ \cite{OPQ} improves upon this by introducing an orthogonal rotation matrix to de-correlate the dimensions before processing with the PQ splitting.

Since, for an item, each SID using OPQ comes from an orthogonal subspace, they do not follow a hierarchical relationship and are typically independent of each other. Consequently, semantic IDs generated using OPQ need not be generated auto-regressively which is a limitation for those generated using RQ-VAE allowing for longer semantic IDs for the same amount of compute. Longer SIDs can capture much more complex item attributes and relationships at the cost of disk space. Xia et al. \cite{2026ACERec_xia2026unleashpotentiallongsemantic} and Hou et al. \cite{2025RPG_hou2025generatinglongsemanticids} use OPQ to generate long SID sequences ($L$ up to 64) which is hard to achieve with RQ-VAE ($L$ typically 4 or 8) due to vanishing residuals and increasing inference time. Both RPG and ACERec deploy parallel decoding strategies that effectively predict the recommended item in a single forward pass.

\subsubsection{Residual Balanced K-Means}\label{subsubsection:Balanced K-Means}
Quantization algorithms such as RQ-VAE for generative recommendation using SIDs suffer from the \emph{hourglass} phenomenon (Kuai et al. \cite{kuai2024breakinghourglassphenomenonresidual}) as codebooks in the middle layers become increasingly concentrated. Since the intermediate layers depend on the residual from the prior ones, the distribution of usage of codewords is non-uniform as shown in Figure \ref{fig:HourglassPhenomenon}. On the other hand, OPQ breaks down the hierarchical nature of semantic IDs, the presence of which is desirable for both  explainability and cataloging. OneRec \cite{2025OneRec_deng2025onerecunifyingretrieverank} and GLIDE \cite{2026GLIDE_damico2026deployingsemanticidbasedgenerative} utilize a variation of K-Means to create codebooks that still maintain the hierarchical nature of semantic IDs.

\begin{figure}
    \centering
    \includegraphics[width=1\textwidth]{images/Hourglass.png}
    \caption{The Hourglass Phenomenon of Semantic IDs \cite{kuai2024breakinghourglassphenomenonresidual}}
    \label{fig:HourglassPhenomenon}
\end{figure}

For a given item embedding $e_i$, the codebook at layer 1 initially consists of randomly assigned centroids $C_1 = \{c_1^1, c_2^1, \cdots , c_K^1\}$ where $K$ is the codebook size. $r_i^1 = e_i$ is the initial residual. For the next layer, the residual is defined using Eq. \ref{eq:ResidualKMeans} where $s_i^1$ is the semantic ID from the first codebook and $r_i^2$ is the residual for the next layer.

\begin{equation} \label{eq:ResidualKMeans}
\begin{split}
s_i^1 = \operatorname*{argmin}_{k=1..K} ||r_i^1 - c_k^1||_2^2\\
r_i^2 = r_i^1 - c^1_{s_i^1}
\end{split}
\end{equation}

This is a similar process to RQ-VAE which continues up to layer $L$. At each layer, the centroids are updated until convergence. Even though authors in \cite{2026GLIDE_damico2026deployingsemanticidbasedgenerative} showcased that this algorithm outperforms RQ-VAE for their specific use case, it does not guarantee that all clusters at all levels are similar in size which leads to inefficient utilization of the codebooks. To ensure uniform utilization, OneRec uses Balanced K-Means which partitions the data such that each cluster has exactly $|I|/K$ items. Unlike RQ-VAE, there is no reconstruction step during training. Other variations of hierarchical clustering also exist to quantize item embeddings.

\section{Architectures}
\subsection{Non-Parametric models}
Authors in \cite{2024ETEGRec_liu2025generativerecommenderendtoendlearnable} provide a brief summary of non-parameteric approaches which can be utilized to generate semantic IDs. Parameter-free techniques typically involve factorization over the co-occurrence matrix or hierarchical clustering to create SIDs which are then used as input for the recommendation module. GPTRec, for instance, uses SVD decomposition of the user-item interaction matrix to extract latent vectors which represent collaborative features of each item. These features are then quantized or binarized to generate semantic IDs for the downstream tasks. SEATER (SEmAntic Tree-structured item identifiERs) recursively uses the constrained variant of K-Means clustering on pre-trained item embeddings to create a tree-like structure which can then be mapped to generate SIDs. Other popular approaches include LSH (Locality Sensitive Hashing) and graph based methods such as HNSW (Hierarchical Navigable Small Worlds). The sequence of nodes traversed in HNSW to get to the item embedding forms the semantic ID sequence for that item.

Parameter-free methods are fast to construct, computationally efficient and easy to implement but the ID generation is decoupled from any downstream tasks. The process is also fixed and does not take into account the nature of the items. They also often rely on static data and are often not suitable for realistic settings where items and interactions change constantly.

Table \ref{table:ModelClassification} briefly summarizes the models that fall into any of the 8 possible combinations for these axes. It is to be noted that not all categories may have models associated with them and not all models may fall strictly into one of these categories. The focus of some of the research may also not be a good fit for such classification. In \cite{2025RPG_hou2025generatinglongsemanticids}, the primary objective of the authors have been to generate long and more expressive semantic IDs using a framework that can generate them in parallel. The classification in Table \ref{table:ModelClassification} does not account for this. This generalized classification, however, allows us to organize the research areas in this space in a way that is more suitable for real-world use since each axis focuses on a different aspect of the generative recommendation process.

Independent training of SID generation and generative recommendation allows the semantic IDs to be decoupled from their usage in recommendation. The SID, in this case, is a more truthful representation of its corresponding item and its content, and not of the item a user is likely to click on next. This is primarily useful if SIDs need to be also used for item organization or for recommending items solely on content similarity. Authors in \cite{JointSR_10.1145/3705328.3759300} have compared the effect of using task-specific SIDs to cross-task SIDs for search and recommendation tasks. Semantic IDs trained for search (from item content) or for recommendation (from interaction matrix) only tend to perform better on their respective tasks but not on the other. Semantic IDs that account for both these tasks provide balanced performance on both search and retrieval. The second axis focuses on the cost aspect of the recommendation process. Training an embedding model tailored to a specific catalog of items may improve the quality of embeddings but in practice that is often costly and infeasible. Using a pretrained embedding model to generate embeddings using item features as input is more cost effective and practical for most use cases. The last axis depicts whether any other data apart from the item contents, such as any user-level preferences and co-occurrence features, is used as part of generating the SIDs. Although some of the listed models utilize user behavior to personalize the recommendations, the user behavior is modeled only using the item sequences. Usage of external information such as user demographics and market research to generate semantic IDs is limited and can be a potential area of research.

For any real-world use case, the appropriate choice of architecture can be narrowed down by asking the following questions:

\begin{enumerate}
    \item Should semantic ID of an item be a representation of its contents or of the item that should follow it in the recommendation sequence?
    \item Is it feasible to train a custom embedding model for encoding the item contents?
    \item Should semantic IDs also encode any other information such as user-level preferences and collaborative features?
\end{enumerate}

Different surveys utilize different ways to classify the works listed in Table \ref{table:ModelClassification}. Authors in \cite{2026_SIDGenRecSurvey} classify each of them across 5 different components of the entire generative recommendation pipeline - Representation, Tokenization, Generative Backbone, Training and Inference. For each component, the approaches are differentiated into various categories based on the methodology followed resulting in a process driven taxonomy. In \cite{2026_SIDSurvey}, authors utilize a much more comprehensive classification methodology which even factors in augmentation during SID construction and SID alignment.

\subsubsection{Independently trained models}
In the world of generative recommendation using semantic IDs, most modeling approaches consist of two major modules - 1. SID generation which is responsible for digesting the item information to generate semantically meaningful sequences of tokens and 2. Recommendation module which is responsible for taking in the historical interaction history and predicting the next item in the sequence. These give rise to two learning paradigms. They can be trained in two stages with item-to-SID trained first and then frozen followed by training of the generative recommendation module (Independent training). Or they can be trained end-to-end with both being refined in a single training loop (Jointly trained). In Figure \ref{fig:JointIndependent}, we provide a generic outline of what differentiates independently trained and jointly trained models.

\begin{figure}
    \centering
    \includegraphics[width=1\textwidth]{images/JointIndependent.png}
    \caption{Generic architecture of Independently trained (Top) and Jointly trained models (Bottom)}
    \label{fig:JointIndependent}
\end{figure}

TIGER \cite{2023TIGER_rajput2023recommendersystemsgenerativeretrieval} provides one of the earliest and simplistic implementation of this approach. Item embeddings are generated using a pre-trained Sentence-T5 from textual item features (title, brand, category, etc. from the Amazon Reviews dataset - Refer Section \ref{subsection:AmazonReviews}) and then quantized using RQ-VAE into three semantic and one collision avoidance token each. Each codeword has a cardinality of $256$. These $1024$ tokens ($256 * 4$) along with $2000$ user tokens, which are hashed from user IDs, form the vocabulary of the T5X model. This model is then trained to take as input the SIDs of the chronologically sorted items from the interaction history with the objective to predict the SIDs of the next item as output. During inference, tokens are decoded using beam search and invalid sequences discarded. Qualitative results showcase that initial codewords capture high level categories from the dataset while the latter capture finer ones.

Authors of TIGER have stated that speed and efficiency was not the objective of their work. RPG \cite{2025RPG_hou2025generatinglongsemanticids} takes on the opposite approach by focusing on very long semantic IDs and generating them in parallel for speed. It replaces RQ-VAE for OPQ to generate SIDs with as much as $64$ tokens compared to $4$ used in TIGER. This, however, creates an issue of interaction history sequence $S'$ being too long when all these SIDs are concatenated. Authors avoid this by implementing an SID embedding aggregation step which produces a compact item representation sequence which is then fed into the generative transformer model. Since semantic tokens here are conditionally independent, Multi-token Prediction (MTP) objective is used to optimize the probability of the target semantic ID against all possible combinations. Inference involves beam search with graph traversal against items with similar semantic IDs to generate the most relevant predictions. RPG showcases that longer semantic IDs are more expressive and cuts down on the inference time compared to TIGER by reducing the number of encoder forward passes per sequence.

OneRec \cite{2025OneRec_deng2025onerecunifyingretrieverank} and SPM-SID \cite{2023SPMSID_singh2024bettergeneralizationsemanticids} use SIDs to recommend videos to users on Kuaishou and YouTube respectively. Singh et al. explore the idea of using SIDs in a constrained setting with fixed embedding table size for generated SID tokens. Once quantized, SID sequences are broken down into subwords using N-gram or more effectively using Sentence Piece models (SPM). SPM groups together co-occurring codes into subwords to reduce the vocabulary of the generative recommendation model which is essential in large-scale production settings with resource constraints. OneRec, unlike other models, focuses on predicting list of high value sessions instead of just the next items. SIDs, quantized using Balanced K-Means, are passed into transformer model based on the T5 architecture which forms the seed model. The encoder encodes the user's historical interactions and the MoE (Mixture of Experts) decoder model to generate the next session sequentially. A reward model is also trained that takes in a candidate session and user interaction history and calculates the reward value. The reward values include session watch time, view probability, follow probability and like probability which is available from the extensive recommendation data. The seed model then generates multiple candidate sessions using beam search and their rewards are calculated. Using the seed model, the candidate sessions and their reward values, iterative versions of the seed models are trained using Iterative Preference Alignment (IPA) to factor in the user preferences via an updated loss function.

\section{Datasets}
\subsection{Amazon Reviews}\label{subsection:AmazonReviews}
Amazon Reviews dataset is one of the most popular benchmark dataset in modern Recommendation Systems (RecSys) research, specifically for generative, sequential and semantic ID based recommendations. It was first introduced in 2014-15 \cite{amazonreview_mcauley2015imagebasedrecommendationsstylessubstitutes} and has been revised once in 2018 and most recently in 2023 with now over 48 million items. Most works do not utilize the entire dataset but limit themselves to one of the various subsets such as Sports, Beauty, Toys, etc. which are based on Amazon's product catalog. The dataset contains title, description and category for each item alongside timestamped interaction history for each user.

\subsection{Yelp}
Yelp Open Dataset is another publicly available dataset for recommendation systems which is periodically updated. Currently, it has over 6.9 million reviews and multiple attributes for various businesses (usually cafes and restaurants) which have been used to benchmark models such as DIGER and LETTER.

\subsection{Other datasets}
OneRec has been tested to generate video recommendations for Kuaishou which is a short video platform whereas SPM-SID was used to recommend videos on YouTube with a corpus of the order of $O(100M)$. Other datasets that have been utilized included advertising datasets from Tencent and movie data from MovieLens.

\section{Metrics and Evaluation}

\subsection{Evaluation of Semantic IDs}
Semantic IDs form a very efficient representation of an item for search and retrieval tasks. Even though they are typically generated from pre-trained embeddings, the process of quantization to generate discrete tokens can still be evaluated across multiple dimensions.

\subsubsection{Invalid IDs}
One major concern with generating semantic ID auto-regressively is that language models can generate invalid sequences of SIDs. The space of valid SIDs is equal to the size of the item space $|I|$ which is orders of magnitude smaller than all the possible combinations. However, authors in \cite{2023TIGER_rajput2023recommendersystemsgenerativeretrieval} showed that this concern is trivial and a trained generative model only predicts invalid IDs about $1\%$ of the time. Even this can be effectively countered using a beam search and filtering out invalid sequences at the cost of computation time.

\subsubsection{Code Distributions}
Diversity in code assignments is necessary to fully utilize the codebooks and prevent all items from sharing the same tokens. As shown in Section \ref{subsubsection:Balanced K-Means}, OneRec achieves this by using an alternate quantization strategy to ensure each codeword in each codebook is efficiently utilized. LETTER \cite{2024LETTER_wang2025learnableitemtokenizationgenerative} achieves a similar objective by augmenting the quantization process of RQ-VAE by factoring in a diversity loss which provides improvements over TIGER, the effects of which can be seen in Fig \ref{fig:LETTERcodeDistributions}.

\begin{figure}
    \centering
    \includegraphics[width=1\textwidth]{images/LETTER code distributions.png}
    \caption{Code assignment distributions using LETTER and TIGER \cite{2024LETTER_wang2025learnableitemtokenizationgenerative}}
    \label{fig:LETTERcodeDistributions}
\end{figure}

It is also important that similar items share SID representations. Authors of UniSID cluster items using the semantic IDs and evaluate their homogeneity using a clustering metric \emph{V-measure} across various levels using the finest category from the Ad60W dataset as the ground-truth. The idea is that items of the same category should fall in the same cluster. It can be seen in \cite{2026UniSID_jiang2026endtoendsemanticidgeneration} that UniSID performs better than models that utilize pre-trained embeddings.

\subsection{Recommendation performance}
The quantitative evaluation of generative recommendation using SIDs can be done using the metrics listed below:

\begin{itemize}
    \item \textbf{Recall@K}: $Recall@K$ tells us how many of the relevant items appear in the top-$K$ predictions of the recommender. When measured with $K = 1$ with only one relevant item, it indicates the perfect next item recommendation. Values of $K$ typically range from $5$ to $20$.
    \item \textbf{Precision@K}: $Precision@K$ tells us how many of the top-$K$ recommended items are relevant.
    \item \textbf{Hit Rate@K}: $Hit Rate@K$ tells us whether at least one relevant item exists in the top-$K$ predictions.
    \item \textbf{nDCG@K}: Normalized Discounted Cumulative Gain measures the ability of the model to rank relevant results at the top and penalize highly ranked irrelevant documents.
    \item \textbf{Session-based metrics}: OneRec \cite{2025OneRec_deng2025onerecunifyingretrieverank} uses session-based metrics to evaluate the predicted session of recommended videos such as \emph{like probability} and \emph{session watch time} for its specific use case.
    \item \textbf{Compute requirements}: Since most models utilize large transformer models, the \emph{time} and \emph{memory} requirements play a pivotal role in their usability. Parallel decoding strategies such as the one used by ACERec provide significant improvement in time required to predict the next item which can play a key role in real-time settings. It is also to be noted how time and memory requirements scale with the size of the catalog and length of the semantic IDs. Generation using auto-regression and parallel decoding tends to be independent of the size of the catalog as long as the length of SIDs is fixed. Time required for inference for auto-regressive models typically scale linearly with the length of SID sequences.
\end{itemize}

In case of auto-regressive decoding of semantic IDs, these metrics are typically measured after generating the entire sequence of semantic IDs, applying any conflict resolution steps if any and mapping the generated semantic IDs to the corresponding item.

\subsection{Recommendation quality}
\subsubsection{Diversity}
It is important for the recommendations to be diverse to prevent echo-chambers and user fatigue. Metrics such as recall do not factor in this objective which is essential for the long-term engagement of the users. In \cite{2023TIGER_rajput2023recommendersystemsgenerativeretrieval}, authors use \textbf{Entropy@K} to measure the distribution of the ground-truth categories of the item. They also show that increasing the temperature during beam search can lead to higher entropy and consequently better diversity. This follows directly from the nature of semantic IDs generated using RQ-VAE (Sec \ref{subsubsection:RQ-VAE}) in which similar items share a common prefix and can be used for a more diverse recommendation.

\subsubsection{Cold-start scenarios}
By their very nature, semantic IDs provide better generalization than random item IDs in cold-start and long-tail problems since they leverage shared semantic features for generative recommendation. As mentioned in Section \ref{subsubsection:RQ-VAE}, beam search decoding using auto-regressive models helps a lot in alleviating cold-start scenarios that plague most recommendation systems. Items which share a lot of prefix tokens with each other can be recommended as alternatives to each other greatly enhancing discovery for all items including new ones. In \cite{2025RPG_hou2025generatinglongsemanticids}, it can be seen that RPG trained with multi-token prediction objective performs quite well even with long semantic ID sequences in cold-start scenarios.

\section{Research areas and real world results}
From Table \ref{table:ModelClassification}, we can see that there are not enough research areas that leverage the power of semantic IDs in conjunction with auxiliary data. Quantization techniques to generate SIDs are also limited to majorly 3 strategies - Residual quantization, Product quantization and clustering. We believe that factoring in user details and domain specific data and utilizing other quantization techniques such as Additive quantization could be potential areas for future research. On the explainability side, most of the quality assessment in this field has been limited to diversity analysis of the generated recommendations. For cases where predictions are steered by instructions \cite{2026GLIDE_damico2026deployingsemanticidbasedgenerative}, human and LLM based evaluations have been used to identify failure scenarios such as language and interest mismatches between the predicted item and user preferences. These failures are not captured by traditional retrieval metrics.

There have also been some attempts to standardize all works in this field to accelerate experimentation with various methodologies. GRID (Generative Recommendation with semantic ID) \cite{2025GRID_ju2025generativerecommendationsemanticids} provides an open-source framework to designed to facilitate easy component swapping but is entirely focused on performance benchmarking and lacks any methodology for fairness assessment. Apart from literature, some of these models have been tested in real world settings. OneRec's A/B testing on Kuaishou’s video recommendation provided positive results with a $1.6\%$ increase in total watch-time but no information has been provided regarding cost and latency. GLIDE at Spotify provided an increase of $5.4\%$ in non-habitual streams per user and an increase of $14.3\%$ in non-habitual streams for new shows. Usage in real world settings can reveal challenges related to infrastructure, deployment and performance opening doors for research in better optimization techniques.
